Upgrade the Receipt Editor into a fully dynamic, database-driven receipt builder. Do not use hardcoded rows, columns, or receipt sections. Everything should be configurable from the admin interface and stored in the database.

Requirements:

• Allow the admin to add, edit, delete, reorder, show/hide, and resize receipt rows and columns.
• Every change must be saved to the database and automatically reflected in the receipt preview, printed receipt, PDF receipt, and emailed receipt.
• Build the editor using reusable React components and a modular architecture.

Create database tables/models for:
- Receipt Layouts
- Receipt Sections
- Receipt Fields
- Receipt Settings

Each field should support:
- id
- section
- label
- databaseField
- visible
- required
- editable
- order
- width
- alignment (left, center, right)
- fontSize
- fontWeight
- textColor
- backgroundColor
- padding
- margin

The admin should be able to insert fields directly from the database instead of typing static text.

Support multiple receipt templates so the admin can switch between layouts.

Implement role-based permissions so only Admin users can modify receipt layouts.

Design the system so any new database field added in the future automatically appears in the "Add Field" menu without requiring code changes.

Maintain backward compatibility with existing receipts and ensure all receipt generation (preview, print, PDF, and email) uses the active saved layout.
